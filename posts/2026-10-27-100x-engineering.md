我身边的大部分程序员对 agent 的理解和开发还不足 1%。

## 1. 管理 5 个对话框和管理 100 个 agent 是完全不同的

大部分人管理少量 agent 的时候不停地切换窗口，新来一个任务就新开一个窗口。你的注意力是割裂的，此时往往是最累的。

瓶颈是注意力带宽。一个人同一时间只能看一个窗口，窗口开得越多，每个 agent 分到的注意力越少。

要提升吞吐，首先要戒掉 micro management 的坏毛病。我不直接管这些 agent，只跟一个 leader 说话。它只做三件事：巡检、转达我的决定、在后台等结果，自己不动手干活。

其次，提升并发最大的挑战是改变 agent 系统的架构，改变信息的输入和处理管道。我用三个思维模型来改：[herdr](https://github.com/herdrdev/herdr) + [zorua](https://github.com/szupzj18/zorua) 管派发和接入，[mnemo](https://github.com/szupzj18/mnemo) 管上下文，每日复盘管演进。

herdr + zorua：把派发和接入自动化。10 月 16 日我新建了 12 个 agent，每个要手工走 6 步，还漏过两次审核框。

后来这些步骤收成了一条命令，每个 agent 自动拿到一个 git worktree、一个 [zorua](https://szupzj18.github.io/zorua/) 账号、一个输出目录，互不踩脚。zorua 保留窗格作为备用控制台。

等结果也不靠盯屏幕。`wait_agent.sh` 订阅终端事件，agent 做完、卡住、超时各返回一个退出码，把 leader 叫醒。

10 月 15 日到 26 日，光本机就开了 357 个会话，最多的一天 76 个。

## 2. 让上下文流动起来

每个 agent 的会话是设备里的第一手资料。其他 agent 在启动时主动去搜索，获取想要的信息。

这样更高效，因为传话会丢细节，还会过时。有一次换 leader，新 leader 照抄了交接文件里的待定清单。我逐项核对，2 项已经过时，2 个窗格早就关了。

所以我把所有 agent、所有设备的会话放进一个索引，叫 [mnemo](https://szupzj18.github.io/mnemo/)。

agent 的自述、读屏和摘要都不算事实：PR 的状态看 `gh pr view`，以前怎么做的搜 mnemo。

这篇文章写到一半换过两次账号。每次新会话都没拿到转述，是自己去读旧会话的原文接上的。

## 3. RSI：让系统持续演进

好的架构是生长的、动态的。这个系统的复盘和持续进化，是架构演进的关键。

![复盘前后的系统：灰色是 10 月 14 日第一次复盘前就有的部分，彩色是之后每晚复盘长出来的，按落在哪一层着色](/img/100x-engineering/system-growth.svg "demo=system-growth")

我每晚十点左右复盘一次，素材是当天的会话原文，都在 mnemo 里。

我从中挑出当天的失误、我反复做的决定、leader 反复做的操作，写成脚本、准则或默认做法，同步进技能库，下一个任务自动带上。

落地前拿当天的记录回放，改前改后各过一遍，没变好就维持原样。

![图 2：每晚复盘](/img/100x-engineering/fig2.png)

纠正落在哪一层，决定了同样的错下次还会不会再犯。poteto 在 *how i shipped 2,500 PRs* 里讲过：agent 会照着上下文里看到的模式做，口头纠正只在当前会话有效。所以纠正分四层，能落在越上面越好：

1. 代码结构：让错误写不出来。
2. lint 和 CI：机器拦下。
3. skill 和 rules：agent 可能没读。
4. 人工 review：PR 一多就漏。

10 月 23 日，任务说明里写了"只读"，agent 照样写了三次 live 数据。其中一次把在用的 mnemo 索引迁了版本，所有会话停止入库约 20 分钟。复盘提议技术隔离，落在第一层。

10 月 25 日落地的 `--isolate` 却只是在 prompt 里加了一段"live 路径只读"。实现它的 agent 做冒烟测试时，又写了一次 live 数据。文字挡不住的错，修它的还是文字。

![四次纠正各落在哪一层：新建 agent 和启动自检升到了代码层；“只读”和进度记录停在规则层，又犯了](/img/100x-engineering/fix-layers.svg "demo=fix-layers")

复盘本身也会被忘。10 月 23 日晚上我说"都落实"的四项，第二天一项都没做。现在采纳的改动派给 agent 去实现，leader 只验收，10 月 25 日一晚落地了 11 项。

十天里，复盘长出了 98 项能力，60 项已经落地。它们都没有提前设计过，每一项都对应一次具体的失误。

![复盘记下的 98 项能力按天累计，可以按落在哪一层或现在的状态着色](/img/100x-engineering/retro-growth.svg "demo=retro-growth")

模型不会因为我变好，变好的是它外面那一层。

## 4. Agent 做完大部分工作以后，程序员的价值是什么

随着我大量地、深入地用 AI 和 agent 去组织我的工作流程，我对软件工程未来的形态越来越不确定。

这个系统真正地逼着我思考：agent 能完成大部分的工作之后，程序员的价值是什么？每晚的复盘还在把我反复做的决定改成默认规则和预授权，我手上的决定一天比一天少。

![工程师做什么、软件为什么值钱、钱从哪来：读者自己选哪些还需要人](/img/100x-engineering/engineer-pick.svg "demo=engineer-pick")

我必须坦白地说，目前我没有答案。

如果你要问我下一个阶段该押注什么，我会回答：去做能让你感到热爱的事情。

作为一个终极的技术乐观主义者，我不会押注在 AI 永远不可能比人更擅长某件事上（这底层是恐惧驱动的，我害怕被 AI 取代，所以我拼命去找 AI 不能取代的工作）。我只会押注在我到底对什么更有热情上。
